餐厅预订系统 · 角色与权限

restaurant-booking-system · 基于后端路由中间件（authenticateToken / requireAdmin）与前端路由守卫的实际代码梳理

一、角色层级图

管理员（admin）— 系统最高权限
  • 客户的全部能力
  • 餐厅管理：新增 / 编辑 / 删除、上传图片
  • 桌台管理：新增 / 编辑 / 删除
  • 预订管理：查看全部、改状态（确认/完成/未到场）、登记付款、删除
  • 用户管理：查看全部、修改角色、删除账号
  • 管理仪表盘：统计报表、热门餐厅
客户（client）— 注册即得
  • 游客的全部能力
  • 查看 / 编辑自己的个人资料
  • 创建预订、查看自己的预订列表与详情
  • 取消自己的预订（待处理 / 已确认状态）
游客（未登录）
  • 浏览首页、餐厅列表（搜索 / 菜系筛选）、餐厅详情
  • 查看桌台与可用时段
  • 注册账号、登录

• 权限在两层同时生效：后端中间件强制校验（越权返回 401「需要提供身份验证令牌」/ 403「需要管理员权限」），前端路由守卫负责隐藏入口（ProtectedRoute 需登录、AdminRoute 需 admin 角色）。
• 业务规则：桌台 2 小时占用窗口的可用性检查对所有人一致；预订状态流转 pending → confirmed → completed / cancelled / no_show；付款仅可对「已完成」预订登记。
• 角色存于 users.role 字段，后端仅接受 admin / client 两种取值。

⚠️ 代码中发现一处不一致：前端「用户管理」的角色下拉框提供了第三个选项「经理（manager）」，但后端角色校验只接受 admin / client，选择「经理」保存会被拒绝（400 角色无效）。如需修复请告知。
